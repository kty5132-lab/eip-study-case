# eip-study — 데이터 형식·개발 가이드

앱 소개와 배포 방법은 [루트 README](../README.md)를 보세요. 이 문서는 **문제·이론 데이터를 추가·수정하는 방법**과 설계 메모입니다.

## 폴더

```
eip-study/
├─ index.html · style.css · app.js    앱 본체 (라우터·퀴즈 엔진·복습·통계·설정)
├─ data/
│  ├─ written.js · written2.js · written3.js   필기 문제 (…2·3.js는 추가 세트)
│  ├─ practical.js · practical2.js    실기 문제
│  ├─ toc.js                          이론 목차 (과목 → 대단원 → 항목 번호)
│  └─ theory1.js ~ theory5.js         필기 이론 (항목 001~157)
├─ sw.js · manifest.webmanifest       오프라인·설치(PWA)
├─ icons/                             앱 아이콘
└─ tools/validate.js                  데이터 검증
```

## 검증

데이터를 고친 뒤 항상 실행하세요. 구조 오류, 정답 번호 범위, 중복 문제, 표의 열 수, `**`·`` ` `` 짝 오류를 잡고 보기를 섞은 뒤의 정답 분포도 보여 줍니다.

```bash
node tools/validate.js             # 전체 검증 (이론이 목차와 어긋나면 실패)
node tools/validate.js --coverage  # 이론 항목별로 연결된 필기·실기 문제 수 출력
```

## 가장 중요한 규칙: 배열의 맨 뒤에만 추가

풀이 기록·이론 진도는 `영역-순번`(예: `w-db-12`, `db:5`)으로 저장됩니다.
**기존 항목의 순서를 바꾸거나 중간에 끼워 넣거나 지우면 기록이 다른 문제에 붙습니다.** 새 항목은 각 영역 배열의 맨 뒤에 추가하세요.
(앱에서 추가한 문제는 별도 저장소에 들어가므로 이 제약이 없습니다.)

## 필기 문제 `data/written*.js`

`[문제, [보기 4개], 정답번호(1~4), 해설, (선택) 코드]`

```js
add('db', [
  ["테이블 S의 score가 80, 90, NULL, 70일 때 AVG(score)는?", ["60", "80", "70", "90"], 2, "집계 함수는 NULL을 제외합니다. (80+90+70)/3 = 80."],
]);
```

- 영역: `design` `dev` `ds` `db` `lang` `basic` `method` `sys`
- 보기 순서는 문제 ID 기반 고정 무작위로 앱이 섞어 보여 줍니다. 원본은 어느 번호가 정답이어도 됩니다.
- 추가 세트 파일은 `add(영역, [...])` 로 기존 배열 뒤에 이어 붙이고, `index.html` 과 `sw.js` 의 파일 목록에 등록합니다.

## 실기 문제 `data/practical*.js`

`[유형, 문제, [허용 정답들], 해설, (선택) 코드]`

| 유형 | 용도 | 입력창 |
|---|---|---|
| `term` | 단답형(용어·빈칸) | 한 줄 |
| `code` | 코드·SQL 실행 결과값, 계산 문제 | 한 줄 |
| `sql` | SQL 직접 작성 | 여러 줄 |
| `desc` | 서술형 (`허용 정답`은 빈 배열, **해설이 모범 답안**) | 여러 줄 |

- 영역: `se` `test` `db` `sql` `os` `sec` `code` `algo`
- 자동 채점은 공백·`. , ; ' " 백틱 ·`·대소문자를 무시하고 허용 정답과 비교합니다. 표현이 여러 가지인 정답은 허용 정답에 모두 적어 두세요.
- 자동 채점은 *제안*일 뿐이고 최종 맞음/틀림은 사용자가 직접 정합니다.

## 이론 `data/toc.js` · `data/theory1~5.js`

목차(`EIP_DATA.toc`)는 `[{ n: 과목, ch: [{ n: 대단원, nos: [항목번호…] }] }]` 이고, 각 항목은 번호로 등록합니다.

```js
add(67, 'A', 'db', '정규화(Normalization)', '한 줄 요약', ['정규화', '1nf', '함수 종속'], [ …블록… ]);
//  번호,  출제등급(A~D), 문제 영역, 제목,         요약,         키워드(관련 문제 검색용),  본문
```

- **키워드(kw)**: 앱이 문제 문장·보기·정답·해설에서 이 단어(대소문자 무시)를 찾아 "이 주제 문제 풀기"를 만듭니다. 문제를 새로 쓸 때 해당 항목의 키워드가 문제에 들어가면 자동으로 연결됩니다.
- 학습 진도는 `S.theory['t'+번호]`(`read`/`confused`)에 저장되므로 **항목 번호를 바꾸지 마세요.**

| 블록 | 형식 |
|---|---|
| 문단 | `["p", "문장 **굵게**"]` |
| 목록 | `["ul", ["항목", …]]` · `["ol", [...]]` |
| 표 | `["table", ["머리글", …], [["셀", …], …]]` (모든 행의 칸 수 = 머리글 수, 빈 칸 불가) |
| 시험 포인트 | `["tip", "문장"]` |
| 코드 | `["code", "여러 줄 코드"]` |

텍스트 안에서는 `**굵게**` 와 `` `코드` `` 만 쓸 수 있고, 그 밖의 HTML은 모두 이스케이프됩니다. 코드 구간 안의 `**`(예: 파이썬 거듭제곱)는 그대로 표시됩니다.
등급(A 매 회차 · B 2회에 1번 · C 3회에 1번 · D 4회에 1번)은 교재 목차 표시를 따랐고 일부는 사진이 흐려 추정한 값입니다.

## 앱에서 가져오는 JSON (설정 → 백업·복원)

```json
[
  { "kind": "w", "area": "db", "q": "문제", "c": ["보기1", "보기2", "보기3", "보기4"], "a": 2, "e": "해설", "code": "(선택)" },
  { "kind": "p", "area": "sql", "type": "term", "q": "문제", "ans": ["정답", "허용하는 다른 표현"], "e": "해설" }
]
```

- 필기 `a`는 1부터 시작하는 정답 번호, 보기는 2~5개까지 허용합니다.
- 같은 문제(영역 + 문제 문장)는 다시 가져와도 중복 추가되지 않습니다.
- 백업 파일(`state` + `custom`)은 같은 입력창이나 파일 선택으로 복원합니다.

## 시험 기준과 영역 대응

모의고사 과목은 설정의 시험 기준에 따라 영역을 묶어 만듭니다 (`app.js`의 `PROFILES`).

| 영역 | ~2026 | 2027~ |
|---|---|---|
| design | 소프트웨어 설계 | 소프트웨어 개발 |
| dev | 소프트웨어 개발 | 소프트웨어 개발 |
| ds (자료구조) | 소프트웨어 개발 | 프로그래밍 언어 활용 |
| db | 데이터베이스 구축 | 데이터베이스 구축 |
| lang · basic (OS·네트워크) | 프로그래밍 언어 활용 | 프로그래밍 언어 활용 |
| method (개발 방법론) | 정보시스템 구축관리 | 소프트웨어 개발 |
| sys | 정보시스템 구축관리 | 정보시스템 구축관리 |

과목당 20문항을 뽑는데, 한 과목의 문제 은행이 20문항보다 적으면 있는 만큼만 출제됩니다. 2027 기준의 `정보시스템 구축관리`(sys)는 현재 63문항입니다.

## 저장소 구조·동작 메모

- **저장**: 브라우저 `localStorage` — 학습 상태 `eip.state.v1`, 내가 추가한 문제 `eip.custom.v1`, 진행 중인 풀이 `eip.session.v1`
- **복습 알고리즘**: 맞히면 박스가 +1(최대 5) 되어 1·3·7·14·30일 뒤, 틀리면 박스 0으로 즉시 재출제
- **오프라인**: `sw.js` 는 캐시를 먼저 보여 주고 뒤에서 갱신(stale-while-revalidate)합니다. **파일 목록을 바꾸거나 큰 변경을 배포할 때는 `sw.js` 의 `CACHE` 버전을 올리세요.**
- 외부 라이브러리·빌드 도구·네트워크 요청이 없습니다.
